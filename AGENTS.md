# AGENTS.md

Guide for AI coding agents (and humans) working on this repo. Read it before
changing anything; it records how the board is built and what bit us before.

## What this is

An open-source replacement controller board for the Das Keyboard 4
Professional. It has an RP2350B, a CH334R USB 2.0 hub (USB-C up, 2 × USB-A
down plus the MCU), a volume encoder, 5 buttons, 3 RGB lock LEDs (WS2812D),
and the key matrix on a 26-way 1.0 mm flex soldered to pads (J4). The outline,
holes and connector positions match the original board.

For current status and next steps see [docs/plan.md](docs/plan.md); for the
design itself, [docs/design.md](docs/design.md).

## Environment

Everything runs in the KiCad automation container
(`ghcr.io/inti-cmnb/kicad10_auto_full`, the same image CI uses). On the
maintainer's machine it's a distrobox called `pcb`:

```sh
distrobox enter pcb -- make <target>
```

- KiCad 10: `kicad-cli`, plus the `pcbnew` Python module (system python3 in
  the container).
- SKiDL and easyeda2kicad go into `.deps/` via `pip --target`, because the
  container's Python has no venv. `make` handles it; scripts run with
  `PYTHONPATH=.deps`.
- Freerouting 2.4.1 (Java) is in the container.
- The host is an immutable Fedora (Bazzite). Don't try to install system
  packages; use the container.

## The pipeline (the board is generated: never hand-edit the .kicad_pcb)

```
hardware/circuit/das4.py  --make netlist-->  das4-controller.net
gen_board.py              --make board---->  placed board (outline, holes, placement, silk)
critical.py + route.py    --make route---->  routed board (hand pre-routes, keep-outs, Freerouting x6, cleanup)
make docs drc fab                         ->  renders, fit-check PDF, DRC, build/jlcpcb/
```

| Target | What it does |
|---|---|
| `make board` | circuit → netlist → **placed, unrouted** board. Overwrites the routed board. |
| `make pretest` | Applies only the hand layout and keep-outs to the placed board and runs DRC (`build/pre_drc.json`). Takes seconds. **Run it before every route.** Expect unconnected items and dangling vias; everything else should be empty. |
| `make route` | `route_best.py`: 6 Freerouting variants in parallel, best kept. About 25 minutes; the machine has 24 cores. Copies both `.kicad_pcb` and `.kicad_pro` into `hardware/`. |
| `make check` | Post-route checks DRC can't do: the router-only crystal keep-out, and vias touching pads. |
| `make docs drc fab` | Renders, fit-check PDF, DRC report, JLCPCB files. These do **not** rebuild the board. |
| `make bom` | `docs/bom.md` with live JLCPCB stock (needs internet). |
| `make parts` | Re-fetch JLC footprints, symbols and 3D models (overwrites `hardware/lib/jlc.*`). |

**Done means:** `kicad-cli pcb drc --refill-zones --format json` reports
0 unconnected and 0 violations outside the cosmetic set, and `make check`
passes. The cosmetic set is `silk_overlap`, `silk_over_copper`,
`silk_edge_clearance`, `malformed_courtyard` (D1–D3 library footprints),
`starved_thermal` and `isolated_copper`. CI
(`.github/workflows/check.yml`) gates on exactly this against the committed
board, so commit the routed board **and** its `.kicad_pro`, which holds the
net classes.

## Where things live

- `hardware/circuit/das4.py`: the circuit. **The GPIO map at the top is the
  source of truth** (J4 pad k → GPIO(40−k), buttons, encoder, LED data, UART
  pads). Part picks are `jlc("MPN", ref, "C-number", value)`. Hand-soldered
  parts carry `Assembly=hand`, which keeps them out of JLC's BOM and CPL.
- `hardware/scripts/gen_board.py`: `MECH` (measured positions of
  connectors, buttons, holes: don't move these without new measurements) and
  `GROUPS` (placement of everything else). Also the silkscreen labels, and
  the paste windows on the exposed pad.
- `hardware/scripts/critical.py`: hand-drawn critical nets, all locked:
  - the RP2350 regulator block (copied from Raspberry Pi's minimal design)
  - the exposed-pad vias, the inward power vias and the +1V1 spine on B.Cu
  - decoupling, crystal, encoder, LED 5 V, the USB_UP coupled pair, CC
    resistors, J4 vias

  `keepouts()` adds the rule areas. It returns the router-only ones, which
  route.py removes after Freerouting.
- `hardware/scripts/route.py`: planes (In1 GND, In2 +3V3), net classes,
  plane fanout (a via per +3V3/GND SMD pad), Freerouting rounds, then
  cleanup (`drop_unused_vias`, `trim_dangling`), GND stitching, and patching
  isolated pour pieces.
- `hardware/lib/jlc.*`: easyeda2kicad output (regenerated by `make parts`).
  `hardware/lib/das4.pretty`: our own footprints (the J4 flex pads).
- `firmware/bringup/`: minimal pico-sdk + TinyUSB test firmware for this
  pinout.
- `docs/`: design notes, measurements, BOM, reviews, plan.

## Design rules we follow (don't break them without a reason)

- **Cost:** JLCPCB assembly, top side only. Prefer Basic parts; the Extended
  ones are limited to the few that need to be. Parts that are easy to
  solder by hand (USB-A, encoder, LEDs, 6 mm switches) are hand-soldered.
- **RP2350:**
  - Follow Raspberry Pi's "Hardware design with RP2350" and the minimal
    design: same regulator parts, the same pin-outward order (VIN cap, +1V1
    cap, then L1), and LX running between the cap pads.
  - L1's polarity dot goes on the +1V1 pad. In JLC's footprint that's pad 2.
  - No copper under L1 or LX on In1, In2 or B.Cu.
  - The regulator's GND joins main GND at one point.
  - See `docs/rpi-guide-check-2026-09-26.md`.
- **GPIO:**
  - Matrix lines stay on GPIO0–39, which are 5 V tolerant.
  - Scan by driving low and reading with pull-ups. Never use internal
    pull-downs (erratum E9).
  - The LED data line is inverted by the 2N7002 level shifter: firmware
    inverts the GPIO44 pad output.
- **Layout:**
  - JLC 4-layer rules: 0.1 mm clearance, 0.2 mm hole clearance, 0.4/0.2 mm
    minimum via.
  - USB_UP is a coupled pair over solid In1. It assumes the JLC04161H-7628
    stackup.
  - Keep-outs: under the USB-A shells (F.Cu), 2.5 mm round the mounting
    holes, the crystal block (router-only), and 0.5 mm of via clearance
    round USB_UP (router-only).

## Lessons (things that cost hours)

- **Every hand pre-route steals a corridor from the autorouter.** When one
  net fails in every variant, look for the hand geometry that walls it off
  (examples: the +1V1 spine vs the QSPI lines, the LED 5 V feed, J4 needing
  vias).
- At 0.4 mm pitch, hand traces must **leave a pad straight** before they
  bend, or they clip the neighbouring pad.
- Freerouting isn't fully deterministic here. Run several variants; one
  variant sometimes scores hundreds of violations, so just ignore it.
- Freerouting runs tracks **through** vias rather than ending at them. The
  cleanup has to test "touching", not "ends at", and link track ends before
  removing a via.
- **KiCad 10.0.5 Python quirks:**
  - `fp.SetField` (there's no AddField).
  - Calling `Flip()` before `board.Add()` segfaults.
  - The bounding box of a flipped pad reads wrong; use position and size.
  - Use `GetBoardPolygonOutlines(outline, True)`.
  - `SquaredDistance(p, True)` measures to the outline only.
  - On a **reloaded routed board**, `GetTracks()` and `VECTOR2I` objects
    break after `Remove()`. Do cleanup inside `route.py`'s own process; for
    a one-off, edit the file by UUID and refill with
    `kicad-cli pcb drc --refill-zones --save-board`.
- Net classes live in `.kicad_pro`. Scoring a board without its `.kicad_pro`
  gives nonsense.

## Reviews

Independent reviews (a separate agent with no stake in the design) are part
of the process:
- `docs/review-2026-09-25.md`: circuit review
- `docs/review-layout-2026-09-25.md`, `docs/review-layout-2-2026-09-25.md`:
  layout reviews
- `docs/rpi-guide-check-2026-09-26.md`: checked against Raspberry Pi's guide
- `docs/firmware-check-2026-09-26.md`: firmware support, plus a real build

After significant layout changes, get a fresh review and record the
follow-up in the review doc.

## Conventions

- Commit as the repo's configured author (`git config user.name/email` in
  this repo). Write messages that explain *why*, and give the DRC result for
  board changes.
- Keep `docs/measurements.md` in sync with `MECH` in `gen_board.py`, and
  `docs/design.md` (GPIO table, results line) in sync with `das4.py`.
- Photos and measurements from the physical keyboard beat assumptions. Mark
  anything estimated from a photo as *photo* in `docs/measurements.md`.
